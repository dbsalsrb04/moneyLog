# MoneyLog

with 바이브코딩

가계부 착착의 JSON 백업을 브라우저에서 분석하는 개인용 소비 대시보드입니다. React · TypeScript · Vite · Recharts로 구현했습니다. 백업 파일을 서버에 보내거나 브라우저 저장소에 저장하지 않습니다. 새로고침하면 다시 파일을 선택해야 합니다.

## 실행

Node.js 24 LTS와 npm이 필요합니다.

```sh
npm ci
npm run dev
```

터미널에 표시되는 로컬 주소를 PC 브라우저에서 엽니다. 기본적으로 `127.0.0.1`에만 바인딩됩니다.

```sh
npm test           # 데이터 처리 단위 테스트
npm run build     # TypeScript 검사 및 프로덕션 빌드
npm run preview   # 빌드 결과 확인
```

브라우저 통합 테스트:

```sh
npx playwright install chromium
npm run test:e2e
```

기존 Chromium을 사용하려면 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`에 실행 파일 경로를 지정합니다. 이 클라우드 환경에서는 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e`로 실행할 수 있습니다.

## GitHub Pages에서 사용

저장소의 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 선택합니다. `main`에 푸시하면 `Deploy to GitHub Pages` 워크플로가 의존성 설치, 테스트, 빌드를 거쳐 `dist`만 게시합니다. Source를 변경한 뒤 자동 배포가 시작되지 않으면 **Actions → Deploy to GitHub Pages → Run workflow**를 실행합니다.

워크플로는 게시 방식이 GitHub Actions인지 먼저 확인하고, 기존 Pages 설정의 자동 전환을 시도합니다. 저장소 권한 때문에 전환이 거부되면 위 Source 설정을 직접 바꾼 뒤 실패한 워크플로를 다시 실행해야 합니다. 브랜치 게시와 빌드 결과 게시를 동시에 유지하지 않습니다.

배포가 성공하면 `https://dbsalsrb04.github.io/moneyLog/`로 접속합니다. 사이트에서 선택한 가계부 파일은 호스팅 서버로 전송되지 않고 브라우저에서 처리됩니다.

원본 저장소를 `Deploy from a branch`로 직접 게시하면 `index.html`이 빌드 전 `/src/main.tsx`를 요청해 오류가 발생합니다. Vite의 빌드 결과를 게시해야 합니다. 빌드의 asset 경로는 상대 경로로 설정하여 `/moneyLog/` 아래에서도 읽을 수 있습니다.

## 구현 기능

- 파일 선택 또는 업로드 영역으로 JSON 파일 드래그 앤 드롭. 한 번에 파일 하나만 처리하며 두 방식에 동일한 검증을 적용합니다.
- JSON 파일 검증, 오류 안내, 파일 교체. 잘못된 새 파일은 기존 분석을 덮어쓰지 않습니다.
- 전체 거래와 원본 테이블을 메모리에 보존합니다. 수입(R)·지출(E)·저축(D)·기록(O) 버튼으로 해당 유형만 월별·일별 집계하며 기본 선택은 지출입니다.
- 하나의 조회 영역에서 **월별 / 일별 / 세부 / 분석** 탭을 전환합니다. 탭을 바꿔도 필터·월별 표시 기간·조회 월·세부 날짜 선택을 유지하며 기본 탭은 월별입니다.
- **분석**은 현재 거래 유형과 필터를 적용한 카테고리별 금액 비중입니다. 기본은 일별·세부의 현재 조회 월 하나이며 월 선택창에서 연도와 관계없이 최소 1개·최대 12개 월을 복수 선택할 수 있습니다. 선택한 월은 탭 전환 시 유지하고 공통 조회 월 변경·새 파일 업로드 시 해당 월 하나로 초기화합니다.
- 분석 오른쪽 위의 두 스위치로 **파이차트 / 막대그래프**, **상위 / 하위 카테고리 기준**을 바꾸며 두 설정은 브라우저에 저장합니다. 상위 기준은 첫 `/` 앞의 분류별로 모든 하위 금액을 합치고, 하위 기준은 거래에 적힌 전체 경로별로 구분합니다. 물음표 아이콘을 호버하거나 키보드로 선택하면 지정된 도움말을 표시합니다.
- 분석 범례는 선택 기간 전체 금액의 **5% 이상인 카테고리 중 금액순 상위 10개**를 표시하고 나머지는 회색 **그 외**로 합칩니다. 차트와 범례는 같은 항목·금액·비중을 사용합니다. 그래프 부분이나 범례에 마우스를 올리면 대응하는 부분이 1.05배 커지고 은은한 그림자를 표시합니다.
- **그 외**는 차트와 범례에서 클릭해 마우스 오른쪽 아래의 팝업으로 전체 포함 카테고리를 확인합니다. `카테고리 | 전체 대비 백분율 | 금액` 순으로 표시하며 각 행은 왼쪽에서 오른쪽으로 100ms 동안 나타나고 다음 행은 80ms 뒤에 시작합니다. 화면 가장자리에서는 팝업 위치를 조정하며 동작 줄이기 설정을 존중합니다.
- 거래 유형 버튼 왼쪽의 **검색**은 전체 기간·전체 유형의 메모를 검색합니다. 검색·결과 영역은 최초 팝업 기준 가로 70%·세로 90%를 유지하며, 데스크톱은 오른쪽에 카테고리·태그 필터를 붙이고 전체 창을 가운데 정렬합니다. 필터는 위아래로 배치하고 각각 스크롤하므로 접거나 펼쳐도 결과 영역을 가리거나 줄이지 않습니다. 입력할 때마다 부분 일치 결과와 수입·지출·저축·기록 순의 합계를 즉시 갱신하며 합계와 금액은 캘린더와 같은 유형별 색상을 사용합니다. 빈 검색어는 전체 내역을 표시하고 영문 대소문자는 구분하지 않습니다.
- 검색의 **카테고리별**·**태그별** 버튼은 다중 선택 필터를 접고 펼칩니다. 검색 필터는 대시보드와 독립적이며 기존 상위 카테고리·OR/AND 규칙을 적용합니다. 결과는 최신 날짜부터 `날짜(요일) | 금액 | 메모 | 카테고리 | 태그` 순으로 표시하고 팝업 내부에서 스크롤합니다. Escape·닫기 버튼·바깥 클릭으로 닫으며 다시 열면 검색 조건을 초기화합니다.
- 모바일에서는 오른쪽 필터를 추가하지 않고 기존처럼 검색창 아래에 접힌 필터를 배치합니다. 검색 입력칸은 고정하고 그 아래 필터·합계·결과를 한 영역에서 함께 스크롤합니다.
- 검색 합산 제목과 합계·결과 블록은 가운데 정렬하고 유형 이름은 각 금액 위에 가운데 정렬합니다. 금액 열은 `999,999,999원`을 표시할 수 있는 폭으로 통일하고 날짜 열은 날짜 텍스트 너비에 맞춥니다. 카테고리 열은 좁게, 여러 태그를 담는 태그 열은 넓게 표시합니다. 메모는 같은 폭의 한 줄 말줄임으로 표시하고 마우스를 올리면 음영을, 클릭하면 오른쪽 위에 전체 내용 팝업을 표시합니다. 화면 경계에서는 팝업 위치를 조정합니다. 내부에서 시작한 텍스트 선택·드래그를 바깥에서 끝내도 검색창은 닫히지 않습니다.
- 월별 그래프의 **다른 유형과 비교하기** 버튼으로 수입·지출·저축·기록 중 최대 두 유형을 선택합니다. 같은 월의 막대 자리를 동일한 너비로 나눠 나란히 표시하고 합계·툴팁·금액 표를 유형별로 제공합니다. 선택은 최소 한 개를 유지합니다. 현재 카테고리·태그 필터를 두 유형에 함께 적용하며, 일별 조회 유형은 유지합니다. 비교 종료 시 기존 월별 그래프로 돌아가며 거래 유형 변경·파일 교체 시 비교 모드가 초기화됩니다.
- **모든 거래 중 가장 최근 `dateKey`** 기준 최근 12·6·3개월, 빈 월도 0원 표시.
- 월 선택과 월별 막대 클릭으로 일별 조회, 월의 모든 날짜 포함, 윤년 지원.
- 카테고리·태그별 다중 선택과 전체 상태 자동 전환. 데스크톱·모바일 모두 선택 시 V 표시 없이 버튼 색으로 상태를 구분합니다. 필터 변경 시 두 차트에 동시에 반영하며 기간과 조회 월 유지.
- 그룹 안 OR, 그룹 사이 AND. 선택 태그가 여러 개 일치해도 거래당 한 번만 합산.
- 상위 카테고리 자체 및 `/` 경계 아래 모든 하위 카테고리 포함, 하위 개별 선택.
- 현재 선택한 거래 유형의 전체 기록에서 사용된 카테고리·태그만 표시합니다. 메타데이터에만 있는 미사용 항목은 숨기며, 현재 기간·필터와 무관하게 목록은 유지됩니다. 유형 전환 시 필터는 전체로 초기화하고 기간·조회 월은 유지합니다.
- 카테고리는 처음에는 상위 분류만 표시하며 오른쪽 화살표로 각 단계의 하위 분류를 접거나 펼칩니다. 접어도 선택 상태와 집계는 유지됩니다. 메타데이터와 원본 거래는 보존합니다.
- 화면 오른쪽 위의 **설정 → 카테고리 선택 방식**에서 기본값인 **트리**와 **개별 버튼**을 선택합니다. 대시보드와 검색을 포함한 모든 카테고리 필터에 적용되며, 개별 버튼은 실제 사용된 전체 경로를 표시하고 상위 분류가 바뀌는 첫 버튼 앞에 세로 구분선을 넣습니다. 방식 전환 시 선택된 필터·기간·조회 월은 유지합니다. 트리에서 이미 선택한 상위 분류는 개별 버튼에서도 해제할 수 있도록 표시합니다.
- 카테고리 선택 방식과 분석의 그래프 모양·카테고리 기준을 브라우저에 저장하여 새로고침 후에도 유지합니다. 거래 데이터와 백업 파일은 저장하지 않습니다. 마우스로 그래프를 클릭할 때 생기던 검은 초점 테두리를 제거하고 키보드 탐색 시에는 초점 표시를 유지합니다.
- `■식비` 같은 이름은 변환하지 않고 독립된 원본 이름으로 보존합니다. 계층은 `/`로만 판별합니다.
- 원화 툴팁, 접근 가능한 금액 표 및 키보드 월 선택, 반응형 레이아웃. 금액 표의 날짜 열은 유지하고 금액 열은 가장 긴 금액 문자열의 실제 너비 × 1.3으로 표시합니다.
- 세부 탭은 일별 그래프와 같은 조회 월·유형·필터를 사용합니다. 사각형 `<`·`>` 버튼으로 하루씩 넘기며 빈 날짜도 포함합니다. 월을 바꾸면 1일로 이동하고, 필터·유형·탭 전환 시에는 현재 날짜를 유지합니다.
- 세부 내역의 월 선택은 `< YYYY년 M월 >` 형태입니다. 좌우 버튼으로 이전·다음 달에 이동하고 가운데 월을 누르면 해당 연도의 12개월을 4열 팝업으로 선택합니다. 팝업 위쪽 `…`을 누르면 앞뒤 12개 연도가 표시되고, 연도를 선택하면 해당 연도의 월 목록으로 돌아옵니다. 2027년의 연도 목록은 2021~2032년이며 좌우 버튼으로 앞뒤 목록을 조회합니다. 바깥 클릭·Escape로 닫기와 방향키·Enter 선택을 지원하며 데이터가 없는 월도 조회할 수 있습니다.
- 세부 내역의 월간 캘린더에서 날짜를 누르면 해당 일자로 바로 이동하고 선택 표시는 좌우 날짜 버튼과 연동됩니다. 일요일부터 토요일까지 실제 요일에 맞춰 배치하며 윤년을 처리합니다.
- 캘린더는 선택한 거래 유형과 관계없이 네 유형을 함께 보여 주되 현재 카테고리·태그 필터를 적용합니다. 각 날짜에 수입은 파란색 `+금액`, 지출은 빨간색 `-금액`, 저축은 초록색, 기록은 회색으로 표시합니다. 금액은 `원` 없이 볼드체로 오른쪽 정렬하며 빈 날짜는 0으로 채웁니다. 날짜는 기존 위치를 유지합니다.
- 세부 내역 표시 이름: `dateKey` → 날짜, `category` → 카테고리, `amount` → 금액, `memo` → 메모, `tags` → 태그. ID와 타임스탬프는 표시하지 않습니다.

거래의 `id`, `part`, `category`, `amount`(유한 숫자), `tags`(문자열 배열), 유효한 `dateKey`가 필요합니다. 잘못된 거래를 조용히 제외하지 않고 행 번호와 함께 파일 전체를 거부합니다. 메모 누락은 빈 문자열로 읽으며 원본은 수정하지 않습니다. `dateAt` 등 타임스탬프를 날짜 변환에 사용하지 않습니다. 선택한 유형에 거래가 없으면 0원 차트를 표시합니다.

```text
src/
  data.ts                       파싱·검증·필터·목록 추출·날짜 집계 (순수 함수)

  analysis.ts                   카테고리 합계·전체 대비 비중·상위 10개 및 그 외
  analysis.test.ts              카테고리 집계·5% 경계·범례 한도·월 선택 테스트
  search.ts                     메모 검색·유형별 검색 합계·요일 표시
  search.test.ts                검색 범위·필터 조합·원본 보존 테스트
  App.tsx                       파일 업로드·공유 상태·대시보드 구성

  components/ViewTabs.tsx       한 영역의 네 탭·키보드 전환
```
